# Правила для ИИ-агентов

Сначала прочитай [ARCHITECTURE.md](ARCHITECTURE.md). Ниже то, что нельзя нарушать.

## Границы

- **Renderer = только UI.** Никаких `fetch` к внешним API, файловых операций и бизнес-логики в `src/renderer`. Нужны данные — добавь метод API.
- **Контракт в `src/shared/ipc.ts`.** Новый метод = `BigBuncherApi` + `API_METHODS` + реализация в сервисе + строка в `src/main/ipc.ts`. Не вызывай `ipcRenderer` напрямую.
- **`src/shared` без рантайм-импортов** (только типы и константы), потому что его используют оба процесса.
- **Сервис = одна область.** Сервисы main вызывают друг друга через экспортированные функции; циклические импорты не допускаются (например, `core/paths.ts` читает настройки, значит settings не импортирует paths).
- Все пути только через `core/paths.ts`. Все HTTP-запросы только через `core/http.ts` (там User-Agent, который требует Modrinth).
- Долгие операции (загрузки, установки) оборачиваются в `runTask()`, чтобы UI видел прогресс и ошибку.
- Ошибки для пользователя бросаются как `new Error('понятный текст по-русски')`; UI покажет его как есть.

## Стиль кода

- TypeScript strict, без `any` (кроме приведения на границах библиотек).
- Имена файлов: `somethingService.ts` для сервисов main, `PascalCase.tsx` для компонентов и страниц.
- Файл до ~300 строк. Если больше, выдели модуль.
- Комментарии объясняют *почему*, а не *что*. JSDoc у экспортируемых функций с неочевидным поведением.
- Весь текст UI на русском. Сообщения в логах и комментарии кода можно писать на английском.
- Стили: токены из `styles/tokens.css`, без хардкода цветов в компонентах (кроме разовых акцентов). Анимации через существующие keyframes в `base.css`.
- Новые зависимости только при реальной необходимости, с записью в таблицу зависимостей в ARCHITECTURE.md.

## Обязательная проверка перед завершением задачи

```bash
npm run typecheck
npm run build
BIGBUNCHER_PAGE=<страница> BIGBUNCHER_CAPTURE=shot.png npx electron .   # посмотреть, что UI не сломан
```

Если менял установку, запуск, скины или моды, прогони смоук-тест (см. README). Он использует временную папку настроек и не трогает аккаунты пользователя.

Сборка exe: `npm run dist` → `release/BigBuncher.exe`.

## Известные тонкости

- `@xmcl/*` закреплены на точных версиях (см. ARCHITECTURE.md). Не обновляй их без проверки установки Forge/NeoForge.
- NeoForge кодирует версию MC в своём номере: `21.1.x` → 1.21.1, `26.1.0.x` → 26.1. Для 1.20.1 используется артефакт `net/neoforged/forge`.
- Все задачи @xmcl получают `downloadOptions` из `core/downloadAgent.ts`. Без него библиотека открывает тысячи соединений разом и ловит Connect Timeout. Шаги установки обёрнуты в `withRetries`.
- Quilt-сборки ищут моды и для `quilt`, и для `fabric`.
- Файлы CurseForge с запретом сторонней раздачи не имеют `downloadUrl`. Используется предсказуемый путь CDN `edge.forgecdn.net`.
- Инъекция скина только для офлайн-аккаунтов. Для Microsoft authlib-injector сломал бы вход на онлайн-серверы.
- Удаление пользовательских данных (сборки, паки, скины с мирами) — только `shell.trashItem` (Корзина), никогда `rmSync`.
- Перед публикацией релиза поднимай `version` в package.json — тег `v<version>` должен быть новым.
- Окно без рамки: области перетаскивания задаются через `-webkit-app-region: drag`, а у интерактивных элементов внутри должно быть `no-drag`.
